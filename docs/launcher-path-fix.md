# 启动器路径导致误报版本未适配

候选版：0.8.0-rc.10，日期：2026-10-30

## 原因和修复

实际安装的 Microsoft Store Codex 26.1023.6621.0 通过了模块指纹校验和额度接口识别。故障来自 `lifecycle-common.ps1` 的 Windows PowerShell 参数数组：逗号与字符串相加的组合被解析为多个数组元素，再由 `Start-Process` 用空格连接，导致 `--app-asar` 的值前后各多出一个空格。它因此无法打开实际存在的客户端文件，控制器回退后，任务和草稿接口显示版本未适配。

现在把每个加引号的路径表达式单独用括号括起来，控制器脚本、状态目录和客户端文件各占一个参数，避免拼接时改变内容。没有修改 Codex 的版本白名单、指纹、原生入口或安装文件。

## 验证范围

新增 `tests/launcher-arguments.cjs` 使用真实 Windows PowerShell 5.1、`Start-CqbController` 和真实 Node 子进程，检查：

- 含空格和中文的安装、状态、客户端文件路径保持原样
- 子进程确实可以找到传入的客户端文件
- 不传客户端文件时仍可启动测试控制器
- 指定 `CQB_TEST_INSTALLED_ASAR` 时，只读校验本机真实 Codex 的额度和任务/草稿模块；本次验证已通过

修复前测试复现了路径首尾多余空格；修复后通过。测试控制器及后台入口均为独立目录里的探针，没有调用实际 Codex 的聊天提交、提醒开关或音乐播放。生命周期测试另行验证真实底栏控制器的加载、升级、单实例、状态保留和恢复。

以前的无界面测试分别覆盖控制器和原生适配器，却没有覆盖启动脚本传递真实客户端路径的组合，这就是之前遗漏此故障的原因。

## 当前客户端

本次诊断时，当前 Codex 主进程没有调试连接端口，之前的底栏控制器和提醒后台都已退出。没有强制关闭或重启它。用户完成当前工作并关闭 Codex 后，可使用项目里的 `开启底栏.cmd` 或修正版 TiBo 启动入口应用。
