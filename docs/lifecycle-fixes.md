# 安装、卸载与多副本启动修复

候选版：0.8.0-rc.5，日期：2026-10-30

本次修复源于 rc.4 的代码审查，不替代完整客户端人工验收。

## 修复内容

1. 后台未运行也可正常卸载。原生命令调用统一捕获退出码，兼容 Windows PowerShell 5.1 的 NativeCommandError 行为。停止一个不存在的提醒后台同样正常返回。
2. 卸载入口先离开安装目录；卸载快捷方式从临时目录启动。中英文 CMD 入口在删除自身后显式退出，避免继续读取已删除的批处理文件。快捷方式只按实际目标路径清理，另一份安装的快捷方式会保留；外部程序仍占用空目录时，不跳过其他清理步骤。
3. 运行中的安装不能被覆盖。安装前检查目录内的 Node 进程与目标文件占用，暂存完整新文件并备份旧文件，复制失败则回滚已改文件及安装记录，首次安装失败也清理自己创建的空目录。私人配置与自行添加的文件保留；回滚失败时保留恢复副本并报告其位置。
4. 不同副本启动时先验证旧控制器归属、协作停止并等待退出，再接管界面。启动操作按状态目录串行化，控制器自身另有命名管道单实例保护。同一副本直接复用；正在发送草稿时拒绝切换安装。接管保留独立后台的开关、刷新计划及待发送轮次。

`-StateDir` 和 `-ShortcutRoot` 可供隔离验证使用，默认入口仍使用原有用户状态与桌面/开始菜单位置。

安装测试使用临时安装目录和隔离快捷方式目录。正常后台检查分支访问的是不存在的隔离状态目录；不是跳过服务查询。升级测试启动的是临时安装目录中的空转 Node，失败注入验证所有已安装文件和安装记录的 SHA-256 完整恢复。中英文卸载入口确实以自己的安装目录为工作目录运行，最终目录和所属快捷方式均删除，进程正常退出。

多副本集成使用无界面的 Edge 与模拟页面，没有连接真实 Codex、发送私人草稿、改变系统音量或安排真实刷新提醒。

本轮未重启或重载承载聊天的 Codex，未替换现有控制器/提醒后台，私人配置保持原散列。仅以只读方式确认新归属检查能够识别现有旧版控制器。当前运行实例继续使用原来的已加载代码，修复版在下次启动时生效。
