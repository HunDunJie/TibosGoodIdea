# 单入口便携版设计与审查

目标：下载并解压后只运行 Start.cmd，不安装、不创建快捷方式、不复制程序到 AppData。设置保存在当前根目录，后台数据在 data，更新版本在 versions。内部脚本保留用于兼容和托盘管理，发行包不提供其他 CMD。

## 编码前三轮审查

1. 使用与目录归属：首次启动先校验产品、文件清单和路径，再建立便携标记。所有新增程序、配置、日志及更新都在所选目录。现有安装标记仍兼容，不把任意目录当作已安装产品。托盘提供设置、打开文件夹和退出 TiBo；退出要恢复界面、停止提醒并取消关机计划。退出后可以直接删除文件夹。
2. 自动更新与故障：每次 Start 都重新获取签名索引；Codex 指纹变化触发适配检查，TiBo 更新按兼容指纹选择最新可用版本，包含功能版。签名、哈希、反回滚和失败隔离继续执行。下载失败使用当前可用版本。运行中的 Codex 不热切换代码，安全时才激活。根启动器先解析已验证版本，再调用该版本的启动协调器，避免老根脚本锁死更新策略。
3. 服务与兼容：同一 Codex 调试端口只能有一个控制器，跨目录也不能重复注入。旧版全局服务只在验证归属且 Codex 已退出后交接；迁移只复制有限的偏好和提醒状态，不复制 PID、日志或关机倒计时，已有便携配置优先。迁移失败保留原文件并可重试。兼容保留旧安装脚本，但不出现在新发行包的用户入口中。测试使用隔离目录、模拟索引和静音音频，不操作真实草稿、音乐或关机。

## 编码后三轮审查

1. 路径与发行清单审查：逐项核对实际差异和 70 项发行清单，CMD 只剩 Start.cmd，源码包以 JSON 夹具保留历史入口供兼容测试，仓库根目录同样只有 Start.cmd。首次采用完整校验及链接拒绝；配置与数据指向当前目录，中文路径通过真实 Windows PowerShell 启动测试。修正了原来 Node UTF-8 输出被 PowerShell 误解码的问题。旧版安装测试在独立的历史入口夹具运行，不向便携发行包回塞别名。
2. 更新与生命周期审查：新启动显式 force/automatic，覆盖新功能版、Codex 指纹变化、每次重新检查、断网、签名失败、撤回和回滚。下载与历史手动检查共享取消锁；切换前重新判断 Codex 是否运行。修正退出服务后被控制器拉起的问题：先取消关机并停控制器，再关后台并确认进程退出。设置窗口不持有启动锁，避免阻塞托盘退出。每个调试端口和便携后台均有独立的跨目录所有权。
3. 迁移与发布审查：隔离 AppData 下运行真实旧服务，验证退出确认、设置与 armed send ID 继承、重复启动、离线、设置保存、托盘退出和关机状态清理；旧文件保留。已有迁移记录也检查旧服务是否被重新开启，避免双重提醒。安装兼容 134 项检查、签名更新和真实后台切换/回滚、三语言托盘检查已通过。当前文档与销售说明同步为便携方式。发布前固定入口继续跑完整 16 组集成测试，结果记录在 work/validation/0.8.0-rc.19/full/result.json，不能以定向检查替代完整门禁。

没有重启用户客户端、发送真实草稿、播放有声音乐或执行真实关机。自动化不替代完整原生客户端及有声人工验收。

发布门禁补审：移除旧 CMD 时发现源码指纹把尚未暂存的删除路径作为临时标记，导致同一实际源码树提交后被误判变化；改为计算实际文件树并增加提交前后一致性回归检查，不降低内容变更必须重新测试的要求。

启动下载补审：每次重新取小索引，但已经暂存且逐文件复验通过的同一更新包直接复用，避免客户端忙碌时每次启动重复下载完整 ZIP；回归检查断言两次索引请求仅有一次完整包下载。
