# Pro 无五小时限制适配

日期：2026-10-30，基于 0.8.0-rc.15，保留之前两轮检查的本地修改

## 行为

- 确认账户没有五小时限制时，隐藏五小时额度和时间，不伪造百分比或刷新时间
- 每周额度、购买点数和可用重置次数仍使用各自的原始数据；完成提醒保持可用
- 定时发送和刷新提醒两个图标保留，禁用后可悬浮查看“不适用”的原因，支持跟随 Codex 的中英日语言
- 后台在处理该状态时先取消旧闹铃、排队闹铃和未结束的发送轮次，再处理定时任务，避免旧时间误触发
- 若正在播放刷新音乐则停止；同一账户的完成提醒音乐不因此中断，原有最长 30 分钟限制不变
- 适用状态随账户额度元数据持久化，后台重启不会恢复已取消的安排；重新读到有限额度后可以手动开启功能，不会自动重开

## 判断边界

已安装客户端的额度结构包含 `plan_type`、`rate_limit.primary_window` 和 `secondary_window`，本地套餐转换识别 `pro`、`promax` 和 `prolite`

只有已知 Pro 类型，且两个窗口明确返回为 `null` 或结构有效的每周窗口，才确认没有五小时限制；也兼容既有的 `planType`、`rateLimit.primary/secondary` 表示
实际返回的五小时窗口优先，不会因套餐名称而忽略它
窗口字段缺失、`rate_limit: null`、窗口结构异常、其他账户的缓存和读取失败都保持未知；购买点数的 `credits.unlimited` 不用于推断五小时限制

旧缓存不能覆盖同一账户更新的判断，跨账户数据仍隔离
底栏安装标识同步到当前版本，避免重新注入时跳过旧版额度解析器
