# 重置卡后的定时发送时间修复

候选版：0.8.0-rc.8，日期：2026-10-30

原来定时发送只在开启时保存目标时间。之后使用重置卡，即使用量接口已经返回新时间，待发送轮次仍保留旧时间。

现在只更新处于等待中的同一轮发送：

- 有效的新用量样本显示可用重置次数减少，或旧目标到点前五小时刷新时间发生变化时，更新目标时间及额度基线
- 自然刷新到点后的正常下一周期数据仍用于执行本轮，不把发送继续推迟一个周期
- 重置后接口暂未返回时间时，保留开启状态、显示暂未取得刷新时间，并继续查询；不把空时间当作立即发送
- 记录最新样本时间，忽略其他窗口的旧缓存；目标时间、轮次编号及样本时间一同保存，后台重启后继续等待新目标
- 已开始或已结束的轮次不会因重置卡重新开启

底栏用量样本增加可用重置次数，悬浮提示继续直接读取后台目标时间，不需要手动关闭再开启。后台启动入口检查已运行后台的版本，避免同目录更新后继续复用旧的发送逻辑。应用本次完整前后台修复时应使用新版的重新加载入口；当前聊天运行实例没有自动重载。

## 验证

- 37 项核心测试通过，新增 7 个场景覆盖目标推迟、提前、空时间或已过期时间等待、旧缓存及重启、旧时间到点后使用重置卡、运行/完成轮次保持
- `tests/send-reset.cjs` 使用真实 FeatureEngine 与无界面模拟页面，验证悬浮提示同步、新旧时间、空时间查询和自然刷新只发送一轮；原生提交替换为计数桩，没有真实草稿发送
- 原生适配测试验证中文、英文、日语下用量样本包含可用重置次数，原有草稿保留与取消检查通过
- 控制器、33 项语言界面检查、设置后台及生命周期测试通过；新增同目录后台版本更新测试，提醒开关、计划与待发送轮次保持
- Node 语法、PowerShell 解析、脚本编码/换行及 Git 差异格式通过

测试没有连接真实 Codex、消耗真实重置卡、发送真实草稿、播放音乐或弹出提醒通知。私人配置 SHA-256 保持不变，完整客户端人工验收仍待用户操作。
