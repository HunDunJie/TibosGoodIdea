# 第二轮复查修复

候选版：0.8.0-rc.9，日期：2026-10-30

## 修复

1. 刷新提醒原先会保留临近响铃的旧计划，以便自然刷新后一分钟仍能提醒。但使用重置卡时也误用了这条规则，甚至在收到新时间的同一次处理里先播放旧提醒。现在先识别重置卡或到点前的时间修正，取消旧计划及排队计划，再检查是否到点。自然刷新仍保留一分钟延迟。
2. 后台保存已知的可用重置次数及用量样本时间，避免短暂缺字段、其他窗口旧缓存或后台重启丢失判断依据。重置卡后时间暂缺或仍为过期值时等待有效的新时间，不恢复旧提醒。恢复定时发送仍须新的原生用量样本确认，保存的元数据不能触发发送。
3. 同目录更新后启动入口原先只核对路径和端口，可能复用旧版底栏控制器。现在同时核对控制器版本，有变化时正常停止旧控制器并加载新版。发送过程中仍拒绝切换；提醒开关、计划及待发送轮次保留。
4. Codex 关闭后，调试页面列表请求会失败，原先位于成功分支的连接清理无法执行，可能使控制器长期驻留。现在失败分支也清理已关闭连接，沿用两分钟启动等待窗口，窗口过后自动退出。独立提醒服务保持运行。

## 验证

- 新增 6 项提醒测试，先复现旧版错误再修复；43 项核心测试全部通过
- 控制器集成测试实际关闭无界面测试浏览器，独立控制器中模拟启动等待窗口已过，验证进程退出且提醒后台存活
- 生命周期测试验证同目录前后台升级、并发副本切换、状态保留、单实例限制和崩溃后的原界面恢复
- 重置卡定时发送页面测试、设置后台测试通过；测试提交替换为计数桩，没有发送真实草稿
- 安装卸载、语法、编码、包内容校验结果记录于 `review-rc9-verification.json`
