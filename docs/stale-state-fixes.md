# 旧控制器状态与异常退出恢复修复

候选版：0.8.0-rc.6，日期：2026-10-30

本次继续修复代码复查发现的两个旧状态问题，保留 rc.5 的安装与多副本修复。

## 行为变化

1. 重启或异常退出后，旧 PID 记录不会阻止启动。只有进程映像、控制器脚本和状态目录全部匹配时，才识别为本工具的控制器；PID 无效、已退出或被无关进程复用时忽略缓存，不向该进程写停止请求。
2. 客户端已关闭时，可以直接恢复或卸载，不必先启动 Codex。仅本机调试端口明确拒绝连接时跳过界面恢复；HTTP 错误、超时等连接异常仍报告失败，卸载不会删除安装文件。
3. 控制器崩溃但客户端窗口仍开着时，单次恢复仍会移除页面底栏及重载注入脚本，保留独立提醒服务。正常启动与单次恢复共用命名管道单实例保护，避免恢复流程绕过正在运行的控制器。
4. 状态文件先写入同目录临时文件，再替换正式文件；Windows 短暂读锁导致 EBUSY、EPERM 或 EACCES 时有限重试，保留原有完整 JSON。恢复脚本与启动脚本使用同一状态目录互斥锁。
