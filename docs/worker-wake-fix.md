# 按钮恢复已退出的提醒服务

候选版：0.8.0-rc.11，日期：2026-10-30

## 行为

退出托盘提醒服务后，底栏中的定时发送、完成提醒和刷新提醒仍可点击。点击任一按钮会先启动服务、读取最新状态及用量，再开启选中的功能。无需再次启动整个 Codex，也无需先手动打开提醒服务。

服务正常运行时，三个按钮仍按开关操作。退出服务已关闭的其他开关不会因为本次点击一起恢复。定时发送先补充当前用量样本，取得有效的下次刷新时间后才能开启。

自动轮询、任务完成事件、鼠标移动及语言同步只连接现有服务，不启动已退出的服务。重新启动后恢复当前 Codex 的语言和提醒通知所需的客户端路径。

## 实现

- 控制器增加仅供点击操作使用的 `wake-worker` 请求，多窗口同时唤醒合并为同一启动过程
- 界面断线时保留按钮可点击，悬浮提示说明点击可重新启动服务
- 点击先读取新服务状态，避免把退出前缓存的开启状态误用于关闭操作
- 点击期间忽略此前尚未返回的旧轮询结果，避免新状态被旧连接错误覆盖

## 验证

控制器集成测试使用真实 CDP、独立 Node 提醒服务和 Windows 托盘播放器。在隔离目录中反复退出服务，分别点击三个按钮两轮，验证单击恢复和开启、旧状态不误关、其他开关保持关闭、日语保持，以及轮询不会自动恢复服务。只替换任务适配器，所有真实草稿提交均被禁止。提醒目标在未来，没有播放音乐或弹出通知。

重置卡定时发送模拟页面、43 项核心测试、79 项界面检查、33 项语言检查和 20 项音量检查通过。语法、编码、包内容和私人配置完整性另见 `worker-wake-verification.json`。

本次没有重新加载当前底栏、启动用户的提醒服务或重启 Codex。应用这次代码更新需重新加载一次底栏；之后退出服务可直接由按钮恢复。
